# 数据治理

## 原则

1. **最小化**：只保存连续支持所需的数据。
2. **目的限定**：治疗流程状态、长期记忆和原始聊天分别管理。
3. **用户控制**：用户可以查看和撤回长期记忆。
4. **可追溯**：摘要和记忆保留来源、时间、置信度与状态。
5. **默认隔离**：RLS 与应用层归属检查同时存在。

## 数据分类

| 数据 | 保存目的 | 默认策略 |
| --- | --- | --- |
| 会话消息 | 当前与历史对话 | 删除会话时按策略级联处理 |
| 会话摘要 | 跨会话恢复关键上下文 | 可重建，不加入无来源推测 |
| 长期记忆 | 稳定偏好、事实、目标、里程碑 | 高置信才 active，允许撤回 |
| 治疗计划/步骤 | CBT 与暴露状态 | 只由受控 transition 修改 |

## 长期记忆准入

可保存用户明确表达且可能长期稳定的偏好、持续目标和治疗里程碑。默认不保存单次临时情绪、模型对人格或诊断的推测、无关高敏感信息及第三方非必要隐私。

## 撤回语义

- 撤回后状态为 `revoked` 并记录 `revoked_at`。
- 默认列表、检索和 prompt 组装只读取 `active`。
- 撤回应幂等，不得泄露其他用户条目是否存在。
- 审计只保留安全与一致性所需的最小元数据。

## RLS 验收

- A 用户不能读取或修改 B 用户数据。
- A 用户不能通过伪造 `user_id` 写入 B 用户名下。
- 子表通过直接 `user_id` 或安全父表关联隔离。
- Service Role 路由执行写操作前仍检查资源归属。

## 日志与供应商

不记录 access token、Service Role、LLM key 或完整敏感对话。错误日志使用 request id、资源 id 和稳定错误码；发送给模型供应商的内容遵循最小上下文原则。
